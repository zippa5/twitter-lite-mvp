# ADR-001: Flask monolith and SQLite for the local MVP

- Status: Accepted for MVP
- Context: Team of at most two; a few weeks; must demonstrate locally with Docker, authentication, posts and persistence.
- Decision: Build a server-rendered Flask monolith using SQLAlchemy + SQLite, Flask-Login sessions and Werkzeug scrypt hashing.
- Alternatives: React + Node + PostgreSQL (more setup, separate services); microservices (deployment/network overhead); Django (more batteries included but larger learning surface).
- Consequences: One command runs the full system; low operational complexity; fast iteration and easy tests. Limits: SQLite write concurrency, server-rendered UI, no independently scaled services. Can migrate to PostgreSQL and a dedicated frontend if growth requires it.
- Security considerations: CSRF tokens on POST, HttpOnly SameSite cookies, server-side validation, escaped templates, no committed secrets. HTTPS, rate limiting, recovery and monitoring remain future work.
