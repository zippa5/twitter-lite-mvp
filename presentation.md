# 10-minute presentation script / timing

| Time | Content |
|---|---|
| 0:00–1:00 | Startup problem, scope and assumptions. |
| 1:00–2:00 | Functional/non-functional requirements and acceptance criteria. |
| 2:00–3:00 | Why Kanban; show live board and task status history. |
| 3:00–4:00 | Architecture diagram, database relationships, ADR trade-offs. |
| 4:00–7:00 | Live demo: register Alice, post, log out, register Bob, post, verify chronological feed, sign in again. |
| 7:00–8:00 | Docker Compose and persistence: restart without deleting volume; refresh feed. |
| 8:00–9:00 | Show pytest results and **actual** successful GitHub Actions run. |
| 9:00–10:00 | Trade-offs, limitations, future work, lessons learned. |

## Evidence to capture before submission
Repository URL, live board with statuses, successful Actions run URL/screenshot, terminal `docker compose up --build`, browser demo and persisted post after restart. Never present planned work as completed evidence.
