# ADR-001: Flask monolith with SQLite

**Status:** Accepted for MVP

## Context
The client requires a functional demonstration within weeks, with secure authentication, durable posts and one-command Docker setup. Team size is one or two.

## Decision
Use Python Flask with server-rendered Jinja templates, Flask-Login sessions, SQLAlchemy, SQLite stored in a Docker volume, and Docker Compose.

## Alternatives
- React + REST API + PostgreSQL: flexible but adds frontend build, API contracts and more services.
- Microservices: independently scalable but creates unnecessary networking and operational complexity for MVP.

## Consequences
Pros: small codebase, quick local setup, straightforward automated testing. Cons: limited independent scaling; SQLite write concurrency constraints; migration tooling should be introduced if the schema evolves.

## Security
Werkzeug scrypt password hashes; CSRF tokens for state-changing requests; HttpOnly and SameSite cookies; secrets via environment variables. Not production-hardened.
