# Methodology — Kanban

Kanban suits a one- or two-person team, uncertain details and short deadline: tasks can be reprioritized continuously without fixed sprint ceremonies.

Workflow: **Backlog → To Do → In Progress → Review / Testing → Done**. Work in progress limit: 2. Prioritize mandatory features before enhancements. Review the board at the start of each work session; move a card to Done only after acceptance criteria and relevant tests pass.

Delivery sequence: (1) foundation and architecture, (2) identity, (3) feed and posts, (4) testing, Docker, CI and presentation. GitHub Issues are backlog records; create a GitHub Projects board and link issues for visual status tracking. Do not claim board evidence until it exists.
