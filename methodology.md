# Methodology: Kanban

Kanban suits one or two students, changing details and a short delivery window better than ceremony-heavy Scrum. Work is pulled from a prioritized backlog and limited to one in-progress item per contributor. Each task has explicit acceptance criteria. Review the board after each coding session and demonstrate completed work weekly.

## Workflow
Backlog → To Do → In Progress → Review / Testing → Done.

## Definition of done
Implementation committed, relevant tests pass, acceptance criteria checked, docs updated, and CI green. Board status should reflect verified work, not intentions.

## Iterations
1. Foundation: requirements, architecture, backlog, repository.
2. Identity: registration, login/logout and password security.
3. Posts: composer, chronological feed and persistence.
4. Delivery: tests, Docker, CI, demonstration and retrospective.

Record actual dates, owners, screenshots and board movement during the project. Do not claim unperformed reviews or CI runs.
